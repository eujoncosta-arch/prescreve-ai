## 3. Contrato de identidade

**Antes:** `runSafetyCheck({ moleculas: string[] })`; nome → primeira entidade; `ambigua` só para moléculas diferentes; variantes tratadas como confirmadas e verificação `completa`.

**Agora:**
- `entidade_ids?: (string | null | undefined)[]`, paralelo a `moleculas` (tamanho diferente → status `erro`).
- Com ID: a entidade do ID **prevalece**, sem fallback por nome. ID inexistente → `nao_verificada` (`id_nao_encontrado`). Texto que não confere com a entidade (nome, sinônimo ou marca dela) → `ambigua` (`id_diverge_do_texto`), `parcial`.
- Sem ID (protocolo antigo): nome que casa com **uma** entidade → `selecao: 'nome_unico'` (confirmada, recuperável). Várias entidades → `primeira_correspondencia_sem_id`, `ambigua` (`variantes_sem_id`), `identidade_confirmada=false`, status `parcial`; os alertas continuam calculados (nada é removido) e a mensagem diz que não foram calculados para uma variante escolhida.
- Novos campos por molécula: `entidade_id`, `entidades_candidatas`, `selecao`, `motivo_ambiguidade`; `identificacao` ganhou `id_explicito`.
- Novos campos por alerta (`rastreio_alertas`): `entradas_nao_verificadas`, `interacao_confirmada`; `texto_bruto` passa a significar "acionado, ao menos em parte, por texto exato de entrada não resolvida".
- Nenhuma entidade é unificada; combinações seguem distintas de monofármacos; variantes seguem independentes e listadas em `variantes_mesma_molecula`.
- Protocolos já salvos **não são migrados nem alterados**; ficam como "identidade não confirmada" quando o nome é ambíguo.

## 4. Estratégia de correspondência

Cada regra fixa referencia um **alvo declarado** (`ALVOS_REGRAS`, mesmas chaves de antes, ids de alerta preservados). Três formas, todas por igualdade:
1. Entidade resolvida: nome ativo normalizado, ou **componente de combinação** (`A + B`, `A/B`), igual a um nome declarado.
2. Entidade resolvida: classe terapêutica cadastrada **começa pelo rótulo** (`BRA`, `BRA — …`, `BRA + Diurético…`) seguido de fim ou separador. "Fibrato" nunca casa `bra`.
3. Entrada não resolvida: texto normalizado **igual** a sigla/alias aprovado (`ieca`, `aine`, `isrs`, `contraste iodado`…). Sempre marcado como não verificado; o alerta sai com `interacao_confirmada=false` e aviso na tela.

Classes são classes: `textoAciona(isrs, 'sertralina')` é falso; o alerta "ISRS + Tramadol" não nomeia sertralina. O dedup CRIT-AUDIT-05 foi mantido, agora por IDs de entidade (`literal:` só para texto não resolvido). A camada de dedup contra alertas da base compara IDs das duas entidades, e só vale quando os dois alvos são moléculas, o que reproduz o efeito prático anterior. Teste-guarda lê o código-fonte e falha se `alvo.includes(` ou `molsLower` reaparecerem.
