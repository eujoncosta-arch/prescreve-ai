## 3. Auditoria da canonicalização (`prescricao-fingerprint.util.ts`)

| Ponto | Achado |
|---|---|
| Correspondência canônico × persistido | Mesmo round-trip JSON do `create`. **Provado** no banco real: 15/15 linhas (teste 14). |
| `undefined`/`null`/ausentes/defaults | Omitidos em objetos (ausente ≡ nulo); `validade_dias` ausente/nulo ≡ 30; `orientacoes:""` ≠ ausente. Testes puros (util.spec) + equivalências no PG (E2.5). |
| Números/strings/arrays | Números como `JSON.stringify` (sem arredondar; `0.1+0.2 ≠ 0.3`); strings exatas; arrays preservam ordem (trocar ⇒ 409, E2.5 3c). |
| **NaN/Infinity — ressalva** | `canonicalizar()` rejeita; porém `fingerprintPrescricao` aplica antes o round-trip JSON (como a persistência), que converte NaN/Infinity em `null` e portanto os **omite** — idêntico ao que seria persistido. Na prática é **inalcançável** via HTTP (`@IsNumber` rejeita NaN/Infinity). A rejeição só é efetiva ao chamar `canonicalizar` diretamente. Registrado; sem alteração. |
| Sem lista branca × propriedades transitórias | Via HTTP, `ValidationPipe(whitelist, forbidNonWhitelisted)` impede propriedades fora do DTO (400), então só entram campos declarados. Em chamada direta ao serviço, qualquer propriedade seria **persistida e canonicalizada igualmente** (identidade = o que é gravado). Risco futuro: se o DTO passar a receber valores **transitórios/server-side** dentro de `medicamentos`, eles entrariam na identidade — exige revisão ao alterar o DTO. |
| `Date`/`BigInt` | Após o round-trip, `Date`→ISO string; `BigInt` lançaria. `canonicalizar` direto trata `Date` como `{}` (uso interno apenas após round-trip). |
| Estabilidade entre versões | A versão `v1` entra no **hash**, mas o valor gravado é só o hex: **não é possível distinguir v1 de uma versão futura** a partir da coluna. **Proposta (não implementada):** gravar o prefixo (`v1:<hex>`) ou coluna de versão, e comparar com todas as versões conhecidas; mudança incompatível exigirá migração/autorização. `v1` **não foi alterada**. |
| PII | Entrada = consulta_id, diagnostico_id, medicamentos, orientações, validade — **nenhum CPF/identificador do paciente**; só o hash é guardado. |
| Arredondamento/transformação de dose | Nenhum (testes puros + PG). |
